# ADR-0012. Отчёт по прогону, дашборд Panel и пакет для борта: один источник данных, автономные документы, проверяемая сборка

- **Статус:** принято
- **Дата:** 2026-11-24
- **Этап:** 11 (Отчёт, дашборд и экспорт на борт)
- **Связанные требования:** T11-01…T11-10, G11-01…G11-08, TRD 5.10, 5.12, 8.4, приложение C

## Контекст

Этап 11 превращает прогон в результат, который можно отдать человеку
и железу: аналитический отчёт, интерактивный дашборд и пакет для борта
RK3588/A733. Требования задают три разных формы одного и того же набора
данных, и главный риск здесь — расхождение: цифра в отчёте, на дашборде
и в манифесте пакета должна быть одной и той же. Нужно решить шесть
вопросов:

1. Откуда брать данные отчёта, чтобы они не расходились с журналом?
2. Чем рисовать графики, если отчёт должен собираться в CI без дисплея?
3. Как сделать HTML автономным, а PDF — с кириллицей и таблицами?
4. Как проверить пакет для борта, не устанавливая вендорские SDK?
5. Как дать дашборду живые виджеты и LaTeX, не открывая внешнюю сеть?
6. Как гарантировать, что предпросмотр в окне совпадает с экспортом?

## Рассмотренные варианты

| Вариант | Плюсы | Минусы |
|---|---|---|
| Отчёт читает `run.sqlite` | Один источник с журналом и дашбордом | Зависимость от схемы этапа 9 |
| Отчёт повторяет прогон | Свежие цифры | Дорого, недетерминированно, расходится с журналом |
| matplotlib для графиков | Привычно, богато | Тяжёлая зависимость, шрифты и кэш, медленный старт |
| Свой PNG-рендер | Нет зависимостей, детерминизм | Только нужные типы графиков |
| SVG в HTML | Векторно, компактно | Qt-печать PDF и вставка в Markdown сложнее |
| Markdown ссылается на PNG | Читаемо в git и редакторах | Нужен каталог рядом |
| HTML с data-URI | Автономен, без сети и CDN | Файл растёт на размер картинок |
| PDF через reportlab | Полный контроль вёрстки | Кириллица и таблицы требуют ручной работы |
| PDF через Qt offscreen | Кириллица и таблицы «из коробки» | Нужен Qt, печать в offscreen |
| Шаблон только встроенный | Просто | FR-REP-08 не выполнен |
| Пользовательский шаблон обязателен | Гибко | Демо-проект ссылается на файл, которого нет |
| Манифест без хэшей файлов | Компактно | Подмена модели не видна |
| sha256 каждого файла + `manifest_hash` | Проверяемо и воспроизводимо | Манифест растёт |
| Вендорские SDK в зависимостях | Конвертация «из коробки» | Лицензии и вес (NFR-LIC-03) |
| Скрипты конвертации отдельным шагом | Лицензионно чисто | Пользователь ставит SDK сам |
| Дашборд на своём HTTP-сервере | Полный контроль | Живые виджеты и LaTeX писать самому |
| Дашборд на Panel | Виджеты, `depends`, LaTeX | Ещё одна зависимость (уже есть по TRD 5.12) |
| Предпросмотр отдельной разметкой | Быстро | Расходится с экспортом |

## Решение

1. **Все три формы читают журнал, а не прогон.** `collect_report_data`
   берёт метаданные, конфигурацию, ряды, ступени и артефакты из
   `run.sqlite` этапа 9; дашборд использует ту же функцию через
   `report_data_from_run`. Симуляция не запускается, прогон не меняется,
   поэтому цифры в Markdown, на панели и в манифесте совпадают по
   построению (T11-01, T11-08).
2. **Графики рисует собственный PNG-рендер.** `core/report/plots.py`
   содержит линейные ряды, гистограммы, столбики и диаграмму план/факт
   по ступеням с растровым шрифтом 5×7. Нет matplotlib — значит нет
   глобального кэша шрифтов, нет скрытого состояния и одинаковый результат
   на Windows и Ubuntu. Ограничение осознанное: нестандартные типы
   графиков добавляются кодом, а не конфигурацией (T11-02).
3. **Markdown ссылается на PNG, HTML встраивает их как data-URI.** Один
   и тот же набор `Chart` даёт `plots/<имя>.png` для Markdown и `data:`
   для HTML; шаблон HTML не содержит `http`, `script` и `link`, поэтому
   файл открывается без сети и без каталога картинок. Это и есть критерий
   G11-01: автономность проверяется поиском внешних ссылок в готовом
   документе (T11-03).
4. **PDF печатает Qt в offscreen-режиме.** `QPdfWriter` +
   `QTextDocument` рендерят тот же HTML, но с файловыми ссылками на PNG:
   base64-ресурсы `QTextDocument` не грузит. Кириллица, таблицы и
   заголовки получаются без ручной вёрстки; при недоступном Qt поднимается
   `PdfUnavailableError`, а не тихая порча файла (T11-03).
5. **Шаблоны Jinja2 встроены в пакет и перекрываются файлом.** Встроенные
   `run_report.md.j2` и `run_report.html.j2` входят в дистрибутив
   (`package-data`), пользовательский шаблон берётся, если файл существует.
   Отсутствующий файл — не ошибка: демо-проект ссылается на шаблон,
   которого может не быть на диске, поэтому в выводы добавляется `INFO`
   о подмене, а битый шаблон остаётся `ReportTemplateError` (T11-01,
   FR-REP-08).
6. **Пороги — декларативные правила с полным совпадением имён.** Порог
   задаётся именем метрики или шаблоном с `*`; шаблон сопоставляется
   целиком (не как подстрока) и берёт худшее значение среди совпавших
   рядов. Выводы уровней `ok`/`warn`/`fail` строятся из значений, а не
   из текста шаблона, поэтому G11-02 проверяется сравнением с метриками
   (T11-02).
7. **Манифест пакета — схема плюс хэши файлов.** `simorph-package/1`
   описывает цель, SoC, конвейер, модели с sha256, калибровку, бюджеты
   и версию приложения; pydantic-схема с `extra="forbid"` отвергает
   опечатки. `manifest_hash` считается по содержимому без полей
   происхождения (`manifest_hash`, `checksums`, `created_at`), поэтому
   две сборки с одними входами дают один хэш, а `verify-package` ловит
   подменённый и лишний файл (T11-05, G11-04).
8. **Конвертация ONNX → RKNN/NBG — отдельный шаг.** В пакет кладутся
   самодостаточные `convert_rknn.py` и `convert_nbg.py` и памятка
   установки; `--convert` запускает конвертацию, только если тулчейн
   найден, иначе возвращает `ok=False` с кодом 2 и подсказкой. Вендорские
   SDK не входят в зависимости (NFR-LIC-03), а сборка пакета остаётся
   возможной без них. Отсутствующая целевая модель — предупреждение,
   а не ошибка: пакет с исходным ONNX полезен и до конвертации
   (T11-06, G11-05).
9. **Дашборд — Panel поверх тех же данных.** `build_dashboard` собирает
   выбор прогона, ползунок порога p95 и галочку «только деградация»,
   `pn.depends` пересобирает блоки без перезапуска, формула масштаба
   выводится в LaTeX (`pn.extension("mathjax")`). Ресурсы встраиваются
   (`pn.config.inline`), сервер слушает только `127.0.0.1` — конфигурация
   с другим хостом отвергается. `simorph dashboard --check` собирает
   панель и печатает число виджетов, блоков LaTeX и время — так G11-07
   и G11-08 проверяются в CI без браузера (T11-08, T11-09).
10. **Предпросмотр в окне — это тот же файл, что уходит в экспорт.**
    `ReportView` пересобирает отчёт целиком на каждое изменение настроек
    и загружает полученный HTML в `QTextBrowser` как локальный документ;
    PNG лежат рядом в каталоге предпросмотра. Отдельной «облегчённой»
    разметки нет, поэтому «в окне одно, в файле другое» невозможно
    (T11-04, G11-03).

## Следствия

- Плюс: один источник данных. Отчёт, дашборд и манифест не могут
  показать разные значения одной метрики.
- Плюс: отчёт собирается в CI без дисплея и без сети: 0,08 с на демо-прогоне,
  Markdown 4,4 КБ, HTML 27 КБ (6 графиков как data-URI), PDF печатается
  в offscreen.
- Плюс: HTML автономен — проверяется отсутствием `http`/`script`/`link`
  в готовом файле, а не обещанием.
- Плюс: манифест воспроизводим: при фиксированном `created_at` сборка
  даёт один `manifest_hash`, а `verify-package` обнаруживает подмену
  модели и лишний файл.
- Плюс: дашборд поднимается за 1,2 с (первый импорт Panel), укладываясь
  в порог 3 с; `--check` даёт 3 виджета и 1 блок LaTeX без браузера.
- Плюс: предпросмотр укладывается в 0,1 с и всегда равен экспорту.
- Минус: собственный рендер графиков ограничен четырьмя типами;
  нестандартная визуализация требует кода.
- Минус: HTML растёт на размер картинок (data-URI), а Markdown требует
  каталог `plots/` рядом с файлом.
- Минус: PDF зависит от Qt; в headless-окружении без Qt остаётся
  `PdfUnavailableError`, и отчёт собирается в MD и HTML.
- Минус: дашборд требует Panel и Bokeh (уже в зависимостях по TRD 5.12);
  LaTeX без локального бандла MathJax остаётся текстом, но данные
  и виджеты работают.
- Минус: конвертация в RKNN/NBG не проверяется в CI — вендорских SDK
  нет. Проверяется контракт: скрипты самодостаточны, а отсутствие
  тулчейна даёт понятный код 2.
- Проверки в гейте: G11-01 (MD и HTML), G11-02 (пороги), G11-03
  (конструктор), G11-04 (манифест), G11-05 (пакет двух целей и суммы),
  G11-06 (CLI без GUI), G11-07 (дашборд ≤ 3 с, LaTeX, живые элементы),
  G11-08 (offline и `dashboard.yaml`).
