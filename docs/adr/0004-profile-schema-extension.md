# ADR-0004. Профиль заказчика: класс без умолчания и неизвестные поля в `extra`

- **Статус:** принято
- **Дата:** 2026-11-21
- **Этап:** 3 (Профиль заказчика)
- **Связанные требования:** FR-PRF-01…FR-PRF-09, T3-01…T3-08, G3-01…G3-07, TRD 5.2, 6.1

## Контекст

Профиль — анкета заказчика из 75 параметров с блоками A–J («Проработка.md»,
3.3.2). Класс параметра С/Э/М/Н определяет его судьбу: С синтезирует
геометрию мира, Э задаёт эмулируемое поведение, М — метаданные прогона,
Н не воспроизводится. От класса зависит проекция в `P_gen`, `P_sim`, `P_hw`
и показатели полноты κ/κ+.

Схема этапа 1 задавала класс по умолчанию (`"M"`) и запрещала неизвестные
поля (`extra="forbid"`, ADR-0002). Для анкеты это плохо: незаполненная
разметка выглядела размеченной, а любая лишняя колонка заказчика
останавливала импорт.

## Рассмотренные варианты

| Вариант | Плюсы | Минусы |
|---|---|---|
| Оставить класс по умолчанию `M` | Импорт проходит без разметки | Ошибка разметки не видна: параметр молча не попадает в прогон |
| Запрещать неизвестные поля | Опечатка в имени поля сразу видна | Анкета заказчика с лишними колонками не импортируется, данные теряются |
| Хранить профиль отдельным файлом | Схема проекта не меняется | Нет атомарного сохранения и единого хэша (нарушает ADR-0002) |

## Решение

1. Класс параметра **обязателен по смыслу, но не по схеме**: `klass`
   по умолчанию `None`. Профиль с неразмеченным параметром сохраняется,
   но проекция блокируется, а валидатор даёт предупреждение
   `profile.parameters.N.class` (T3-03).
2. Неизвестные поля профиля и параметра **не теряются**: импорт складывает
   их в `extra` раздела и параметра, экспорт возвращает на прежнее место.
   `extra="forbid"` остаётся для остальных разделов проекта.
3. Параметр несёт `block` (A–J), `target` (`P_gen`/`P_sim`/`P_hw` или
   `None`) и `projection` — список ключей вектора. Инварианты:
   - класс `N` не имеет ни `target`, ни `projection`;
   - классы `C` и `E` обязаны иметь `target` — иначе проекция блокируется;
   - класс `M` без `target` допустим: часть метаданных в прогон не идёт.
4. Раздел несёт флаг `nda`. NDA-профиль экспортируется только в каталог
   из `SIMORPH_NDA_ROOTS`; профиль без флага, но со ссылкой на NDA-каталог,
   тоже не экспортируется (T3-06).
5. Экспорт — обёртка `{schema_version, export_version, hash, profile}`;
   абсолютные пути в строковых значениях заменяются именем файла (T3-07).

## Следствия

- Плюс: анкета импортируется как есть, лишние колонки сохраняются
  и возвращаются заказчику при экспорте.
- Плюс: неразмеченный параметр виден в таблице, блокирует проекцию
  и не может молча выпасть из прогона.
- Минус: для профиля ослаблен `extra="forbid"`, поэтому опечатка
  в известном поле выглядит как неизвестная колонка. Компенсация — отчёт
  импорта и команда `simorph profile check`, которые перечисляют
  сохранённые поля.
- Минус: изменение схемы меняет golden-эталон `tests/golden/demo_project_v1.json`;
  перегенерация обязательна и зафиксирована в `tests/test_golden_core.py`.
- Проверка в гейте: G3-01 (импорт с неизвестными полями), G3-03 (класс
  блокирует проекцию), G3-06 (изоляция NDA), G3-07 (переносимость экспорта).
