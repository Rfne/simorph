# ADR-0001. Python 3.13.7, сборка PyBullet из sdist и версии из метаданных

| Поле | Значение |
|---|---|
| ID | ADR-0001 |
| Дата | 2026-11-20 |
| Статус | принято |
| Этап WP | 0 (задачи T0-01, T0-02, T0-06) |

## Контекст

Проект зафиксирован на Python 3.13.7 (TRD, NFR-COMP-03). Перед началом работ
проверялась совместимость всего стека на целевой версии. Проверка проводилась
на Windows 11, Python 3.13.7, в чистом venv.

Результаты проверки (PyPI, ноябрь 2026):

| Пакет | Наличие wheel для cp313 | Итог |
|---|---|---|
| torch 2.15.0 | есть | устанавливается |
| openvino 2026.4.1 | есть | устанавливается |
| PyQt6 6.12.1 | есть (abi3) | устанавливается |
| opencv-contrib-python 5.1.0.95 | есть (abi3) | устанавливается |
| numpy 2.5.5 | есть | устанавливается |
| **pybullet 3.2.7** | **нет (последний wheel — cp311)** | **собирается из sdist** |

Сборка PyBullet 3.2.7 из sdist на 3.13.7 прошла успешно при наличии
MSVC Build Tools 2019; получен wheel `pybullet-3.2.7-cp313-cp313-win_amd64`.
На Linux аналог требует `build-essential`.

Отдельно выяснилось: импорт PyBullet печатает баннер сборки в stdout через
консольный handle, минуя файловый дескриптор. Ни `contextlib.redirect_stdout`,
ни `os.dup2` его не перехватывают, поэтому JSON-вывод CLI был бы испорчен.
Импорт torch и openvino к тому же занимает секунды.

## Рассмотренные варианты

| Вариант | Плюсы | Минусы |
|---|---|---|
| A. Откат на Python 3.12 | готовые wheel для PyBullet (cp311/cp310) | нарушает NFR-COMP-03, откат всё равно не даёт cp312-wheel для PyBullet |
| B. Замена PyBullet другим движком | нет проблем сборки | ломает ADR-01, требует пересмотра TRD и WP |
| C. Сборка PyBullet из sdist на 3.13.7 | целевая версия сохранена, стек проверен | нужен компилятор в окружении и CI; сборка ~2–3 мин |
| D. Версии через импорт модулей | «настоящая» версия runtime | баннер ломает JSON, torch добавляет секунды к каждой команде |
| E. Версии через `importlib.metadata` | мгновенно, без импорта, чистый JSON | не проверяет фактическую загрузку модуля |

## Решение

1. Остаёмся на **Python 3.13.7**. PyBullet ставится из sdist; компилятор
   объявлен требованием окружения (MSVC Build Tools на Windows,
   `build-essential` на Linux) и устанавливается в CI.
2. Версии в `simorph version` берутся из **метаданных дистрибутивов**
   (`importlib.metadata`), кроме версии Qt (`QT_VERSION_STR`) и SQLite
   (`sqlite3.sqlite_version`). Тяжёлые модули в команде `version` не импортируются.
3. Фактическая загрузка модулей проверяется отдельно: сейчас — Qt через
   `simorph selftest --ui`, для PyBullet/OpenCV/Torch проверка появится на
   этапе 4 вместе с первым использованием.

## Следствия

- `simorph version` выполняется мгновенно и всегда даёт чистый JSON —
  требование G0-01 выполнимо.
- `simorph version` показывает версию дистрибутива, а не `__version__`
  модуля; для OpenCV это `5.1.0.95` вместо `5.1.0`, для torch — `2.15.0`
  без суффикса `+cpu`. Для отчётов и манифестов это корректнее.
- CI обязан иметь компилятор на обеих ОС, иначе установка упадёт.
- Появляется риск: обновление Python до 3.14 потребует повторной проверки
  сборки PyBullet (wheel по-прежнему нет).
- Затрагиваются: NFR-COMP-03, NFR-COMP-04, G0-01, G0-08, риск
  «Python 3.13.7 и совместимость PyBullet/PyTorch/OpenVINO» (TRD 12).
