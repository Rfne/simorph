# simorph

Настольная среда калибровки бортовых конвейеров патрульного робота (НРТК/БВС).
Проект учебный: магистерская диссертация ИТМО, направление 27.04.03.

`simorph` собирает, проверяет и калибрует бортовой «разум» на PC-прототипе
до переноса на целевые платы RK3588 (RKNN) и A733 (ACUITY/NBG). Командный
контур, ГИС, BIM и ЭДО в границы проекта не входят.

Документация:

- `docs/TRD-v1.0.md` — технические требования;
- `docs/WP-v.1.0 (release-0, MVP).md` — рабочий план Release-0;
- `docs/adr/` — архитектурные решения;
- `CHANGELOG.md` — история изменений.

## Требования

- Python **3.13.7** (ровно эта версия; фиксируется `.python-version` и CI);
- Windows 10/11 — основная платформа, Ubuntu 24.04 — вторичная;
- для сборки PyBullet из исходников на Windows нужны MSVC Build Tools,
  на Linux — `build-essential` (готовых wheel для Python 3.13 нет).

## Установка

```bash
python -m venv .venv
# Windows: .venv\Scripts\activate
# Linux:   source .venv/bin/activate

python -m pip install --upgrade pip
pip install -r requirements-dev.lock
pip install -e . --no-deps
```

`requirements.lock` — только runtime, `requirements-dev.lock` — runtime и
инструменты разработки. Оба файла генерируются `pip-compile` из `pyproject.toml`.

## Проверка окружения

```bash
simorph version            # человекочитаемый список версий
simorph version --json     # машиночитаемый вывод
simorph selftest           # проверка обязательных зависимостей
simorph selftest --ui --offscreen   # Qt без дисплея (как в CI)
```

Коды возврата: `0` — успех, `1` — ошибка данных или конфигурации,
`2` — внутренняя ошибка. Лог пишется в stderr, JSON-lines — в `--log-file`.

## Работа с проектом

```bash
simorph project new examples/demo/project.json --name demo   # создать
simorph project validate examples/demo/project.json          # проверить
simorph project migrate examples/demo/project.json           # мигрировать
simorph project hash examples/demo/project.json              # sha256
```

`project.json` — один переносимый документ из семи разделов: `project`,
`profile`, `world`, `agent`, `exercise`, `pipeline`, `report`. Неизвестные
поля запрещены, у каждого раздела свой `schema_version`. Запись атомарная:
рядом появляются `.bak` (предыдущая версия) и `.lock` (на время работы).
Решение и последствия — `docs/adr/0002-project-json-document.md`.

## Профиль заказчика

```bash
simorph profile project examples/profiles/agroforce.json   # κ, κ+ и векторы
simorph profile check   examples/profiles/agroforce.json   # импорт и отчёт
simorph profile export  examples/profiles/agroforce.json -o profile.export.json
```

Профиль — анкета из 75 параметров с блоками A–J. Каждый параметр размечен
классом: С синтезирует геометрию мира, Э задаёт эмулируемое поведение, М —
метаданные прогона, Н не воспроизводится. Проекция раскладывает параметры
по векторам `P_gen`, `P_sim`, `P_hw`; полнота считается как κ = (С + Э)/75
и κ+ = (С + Э + М)/75. Параметр без класса блокирует проекцию — умолчания
нет намеренно.

Импорт не теряет данные: неизвестные колонки анкеты сохраняются и
возвращаются при экспорте, ошибка JSON сообщается со строкой и колонкой.
Экспорт пишется обёрткой `{schema_version, export_version, hash, profile}`
и не содержит абсолютных путей. Профиль с флагом `nda` экспортируется
только в каталог из `SIMORPH_NDA_ROOTS`. Эталонные заказчики —
`examples/profiles/`; решения — `docs/adr/0004-profile-schema-extension.md`.

## Мир и 3D-сцена

```bash
simorph world build  examples/demo/project.json            # статистика сцены
simorph world build  examples/demo/project.json --limit 500
simorph world render examples/demo/project.json -o scene.png \
    --width 640 --height 480 --hour 15 --precipitation snow
```

Сцена собирается из `world.json`, профиля и seed: рельеф, зоны, здания,
установки, деревья и водоёмы. Явные объекты мира авторитетны, недостающие
генерируются детерминированно, поэтому один seed даёт одну и ту же сцену.
Лимит — 1000 объектов: лишние не строятся, в замечания попадает
предупреждение. `world render` пишет PNG и JSON рядом с камерой, светом,
погодой и диапазоном глубины — по нему снимок воспроизводится.

Рендер работает headless (PyBullet `DIRECT` + TinyRenderer) и не требует
дисплея или GPU; ground truth — глубина, маски по id объектов, позы
и ключевые точки — считается из кадра и геометрии независимо. Решение
и ограничения — `docs/adr/0005-bullet-direct-tiny-renderer.md`.

## Агент

```bash
simorph agent build    examples/demo/project.json          # дерево, сенсоры, P_hw
simorph agent validate examples/demo/project.json          # физическая проверка
simorph agent export   examples/demo/project.json -o agent.urdf
simorph agent preview  examples/demo/project.json -o agent.png \
    --width 640 --height 480
```

Агент описывается звеньями и суставами: кинематическое дерево даёт мировые
позы, массу, центр масс и инерцию по Гюйгенсу — Штейнеру. Цикл, два
родителя или недостижимое звено — это замечание с путём к полю, а не
исключение. Сенсоры девяти типов публикуют детерминированные данные
(показания зависят от seed и времени), актуаторы семи типов принимают
команды с ограничением диапазона и скорости привода.

Бортовые константы `P_hw` — 35 значений TRD 5.4.1 в пяти группах
`TC-DYN`, `TC-SEN`, `TC-CMP`, `TC-ENE`, `TC-COM`; они хранятся в проекте
вместе с агентом. Валидатор проверяет тягу против веса с запасом 10 %,
массу и инерцию, бюджеты CPU/GPU, энергию и канал связи; ошибка блокирует
запуск, предупреждение — нет.

`agent preview` пишет PNG и JSON без фотореализма: звенья плоскими цветами,
зоны обслуживания камер и дальномеров, пересечения габаритов подсвечены.
Экспорт — URDF-подобный XML: стандартные `link`/`joint` плюс расширения
`simorph:sensor`, `simorph:actuator` и `simorph:hw` с явными единицами.
Эталонные агенты — `core/agent/reference.py` (НРТК `NRTC-01` и БВС
`BVS-01`), решение — `docs/adr/0006-agent-model-and-urdf.md`.

## Миссии

```bash
simorph mission build    examples/demo/project.json            # граф и бюджет
simorph mission validate examples/demo/project.json            # пять классов замечаний
simorph mission export   examples/demo/project.json -o mission.yaml
simorph mission export   examples/demo/project.json -o ex.yaml --exercise-only
simorph mission import   mission.yaml                          # только чтение
```

Упражнение содержит миссии, миссия — граф из двенадцати типов элементов
MVP: `start`, `waypoint`, `transit`, `observe`, `dwell`, `activate_sensor`,
`capture`, `return_to_base`, `abort`, `loop`, `parallel`, `condition`.
Граф даёт порядок обхода и слои раскладки; цикл допускается только через
`loop` с явным лимитом итераций, недостижимый элемент — предупреждение,
битая ссылка — ошибка.

Бюджет миссии считается по критическому пути: ветви `parallel` идут
одновременно, поэтому миссия заканчивается, когда заканчивается самая
долгая ветвь. Валидатор проверяет пять классов ошибок: ссылки, граф,
обязательные входы, тайминги (TTL против длительности и бюджета) и
geofence с высотой 0…120 м, а также совместимость сенсора с элементом
наблюдения.

Обмен — JSON или YAML (формат выбирается по расширению). Импорт всегда
read-only: миссия из файла или пакет командного контура (`tasks`, `route`,
`constraints`, `coordination`, `degradation`) читается, но исходный файл
не перезаписывается. Решение — `docs/adr/0007-mission-graph-and-exchange.md`.

## Симуляция

```bash
simorph sim run    examples/demo/project.json --duration 2
simorph sim run    examples/demo/project.json --scale 2 --record run.jsonl
simorph sim run    examples/demo/project.json --latency-ms 3 --loss 0.2 --desync-ms 0.3
simorph sim replay run.jsonl                                  # сверка хэшей без физики
```

Прогон идёт с фиксированным шагом: один такт всегда сдвигает время сцены
на `step_s` (по умолчанию 1/120 с — по частоте сенсора), поэтому метки
кадров и состояние не расходятся. Масштаб времени мягкий: при нехватке
производительности такт выполняется дольше планового интервала, но не
пропускается. `budget_ms` ступени и `fps` источника — плановые ориентиры;
на интервале 1 с времени сцены считаются `k = T_факт / T_план`,
`stage_plan_ms`, `stage_actual_ms`, `stage_overrun_ms`, `queue_depth`
и `queue_wait_ms`, а сводка хранит гистограмму `k`, p50/p95, долю
интервалов за планом и вклад каждой ступени. Отбрасывание кадров —
только явный режим `--realtime-drop`, по умолчанию он выключен.

Кадры идут через кольцевой буфер на 2–4 слота в разделяемой памяти
с метками `t_fsin_ns` (время сцены) и `t_monotonic_ns` (время PC).
Инжекция деградации задаёт задержку сенсора, долю потерь,
рассинхронизацию ±0,5 мс и джиттер выдержки с воспроизводимым seed.
Супервизор ведёт состояния `idle → running ⇄ paused → finished` и
`interrupted`, окна элементов по бюджету миссии, таймеры NPU-транзакций
и очередь фоновых задач; сбой такта не выходит наружу, а переводит прогон
в `interrupted` с читаемыми артефактами. `sim replay` читает записанный
поток и сверяет хэши кадров и монотонность меток, не запуская физику.
Решение — `docs/adr/0008-simulation-and-supervisor.md`.

## Конвейеры

```bash
simorph pipeline build    examples/demo/project.json          # граф, слои, план
simorph pipeline validate examples/demo/project.json          # порты, параметры, циклы
simorph pipeline run      examples/demo/project.json --frames 120 --fps 120
simorph pipeline sources  examples/demo/project.json --snapshot
simorph pipeline sources  examples/demo/project.json --check   # код 1 при stale
```

Конвейер — граф типизированных портов: 12 типов (`frame.mono`,
`frame.color`, `frame.stereo`, `disparity`, `depth`, `points`, `features`,
`tracks`, `roi`, `detections`, `embeddings`, `events`). Порт `events`
принимает любой результат, поэтому приёмник журнала подключается к любому
узлу. Несовместимое ребро блокируется с указанием обоих портов и их типов;
циклы, дубли, неизвестные типы, порты и незаполненные обязательные
параметры — ошибки, неподключённые входы и выходы — предупреждения.

Реестр узлов общий для редактора, валидатора и исполнителя: вычислительный
контур (`rectify`, `sparse.detect`, `sparse.track`, `sparse.stereo`,
`dense.stereo`, `roi`, `fusion`, `event`) укладывается в 5 мс плана на
кадр, нейросетевой (`preprocess`, `inference`, `postprocess.nms`,
`head.detection`, `head.embedding`) — в 400 мс p95. Задержка узла равна
плану или задержке бэкенда; очередь считается по времени сцены, а кадры
отбрасываются только при явном `--realtime-drop`. Отчёт несёт метки
`t_fsin_ns`/`t_monotonic_ns`, задержки по узлам, глубину и ожидание
очереди и число отброшенных кадров.

Инференс и кроп отделены швами: `InferenceBackend.infer()` и `RoiChannel`.
Замена заглушки на ONNX/OpenVINO/NPU-бэкенд не меняет узлы и вызывающий
код. Исходники PC-прототипа открываются только для чтения; снимок
`project.json.sources.json` хранит хэши, а изменение файла после снимка
даёт статус `stale` со списками изменённых, добавленных и удалённых
файлов. Решение — `docs/adr/0009-pipelines.md`.

## Журнал прогонов

```bash
simorph sim run examples/demo/project.json --log run.sqlite   # записать прогон
simorph pipeline run examples/demo/project.json --log run.sqlite
simorph runs list run.sqlite --kind pipeline --limit 10       # список
simorph runs show run.sqlite --last --metric node.src.p95_ms  # ряды
simorph runs export run.sqlite -o metrics.parquet --format parquet
simorph runs annotate run.sqlite <run_id> --frame 12 --class-id person
simorph runs prune run.sqlite --keep-last 20 --dry-run
```

Журнал — отдельный файл `run.sqlite` рядом с проектом: прогоны неизменяемы
и растут быстрее документа, поэтому `project.json` остаётся компактным,
а журнал можно архивировать и чистить отдельно. Схема — шесть таблиц:
`runs`, `run_events`, `metrics`, `artifacts`, `annotations`, `settings`;
режим WAL, внешние ключи и индексы по прогону, имени метрики и времени.
Ряды пишутся батчами по 5000: 10^5 строк записываются меньше секунды,
а незавершённый батч откатывается целиком. Прогон, оставшийся в статусе
`running` после kill, при следующем открытии помечается `interrupted` —
база открывается без ручного ремонта. Экспорт в CSV и Parquet сохраняет
типы: `id`, `t_ns` и `seed` — целые, `value` — число с плавающей точкой.
Решение и последствия — `docs/adr/0010-run-logs.md`.

## Датасет и дообучение

```bash
simorph dataset build datasets/demo --log run.sqlite      # сборка из сцен
simorph dataset info datasets/demo                        # сводка и манифест
simorph train datasets/demo --epochs 120 --log run.sqlite # обучение головы
simorph eval datasets/demo --checkpoint datasets/demo/training/checkpoint.pt \
    --log run.sqlite                                      # mAP, recall, p95
simorph export-onnx datasets/demo/training/checkpoint.pt  # ONNX и сверка
```

Датасет собирается из сцен PyBullet: кадр, рамки, маска, ключевые точки
и метка времени снимаются одним рендером, поэтому разметка не может
разойтись с изображением. Манифест хранит sha256 каждого файла и хэш
содержимого: две сборки с одним seed дают один манифест, с разным — разные.
Сплиты строятся по сценам, так что кадры одной сцены не попадают
одновременно в train и val. Аугментация (шум, экспозиция, размытие,
отражение, потеря кадров, рассинхронизация метки) выводит параметры
из `(seed, номер кадра)`, поэтому воспроизводима; в обучении она
по умолчанию выключена — на синтетике она снижает качество.

Голова — маленькая свёрточная сеть с выходом в сетке 24×18: тепловая карта
классов, логарифмы размеров и смещения центра. Чекпойнт хранит веса, форму
входа, конфигурацию и историю, поэтому отмена и `--resume` не теряют
прогресс. Метрики (`mAP@0.5`, `recall@FPPI`, p95 задержки) пишутся в тот же
`run.sqlite` с префиксами `eval.*` и `train.*`. Экспорт ONNX фиксирует вход
`[1, 3, 72, 96]` и три выхода; расхождение с PyTorch проверяется эталонной
реализацией ONNX (допуск 1e-4), а прогон в OpenVINO пишется в отчёт отдельным
числом — его ядра зависят от CPU. Решение — `docs/adr/0011-dataset-training.md`.

## Отчёт по прогону

```bash
simorph report run.sqlite -o reports/last                    # MD и HTML
simorph report examples/demo/project.json <run_id> \
    --format md,html,pdf --sections metadata,metrics,conclusions
simorph report run.sqlite --threshold k.p95=1.4 --json        # порог и машинный вывод
```

Отчёт собирается из журнала: метаданные прогона, конфигурация, метрики,
графики, пороговые выводы и таблица «план/факт» по ступеням. Секции
включаются и выключаются (`metadata`, `config`, `metrics`, `plots`,
`conclusions`, `scale`), форматы — `md`, `html`, `pdf`. Графики рисуются
собственным рендером без matplotlib: PNG-ряды, распределения и столбики
план/факт; Markdown ссылается на `plots/*.png`, а HTML встраивает те же
картинки как data-URI — файл открывается без сети, каталога картинок
и внешних CDN. PDF печатается через Qt в offscreen-режиме, поэтому
кириллица и таблицы не ломаются. Шаблон Jinja2 можно заменить своим:
путь задаётся в разделе `reports` проекта или флагом `--template`;
отсутствующий файл не ошибка — берётся встроенный шаблон, а подмена
видна в выводах отчёта. Пороги выводов (`k.p95`, `frames.dropped`,
`eval.map50`, `eval.latency_p95_ms`) перекрываются флагом
`--threshold ИМЯ=ЗНАЧЕНИЕ`. Решение — `docs/adr/0012-report-dashboard-package.md`.

## Дашборд прогона

```bash
simorph dashboard examples/demo/project.json --check          # сборка без сервера
simorph dashboard run.sqlite --run <run_id> --port 5006       # локальный сервер
panel serve examples/demo/reports/dash_run.py --show          # источник напрямую
```

Дашборд — форма того же отчёта: те же ряды из `run.sqlite`, те же графики
и те же выводы, но с живыми виджетами — выбор прогона, порог задержки p95
и галочка «только деградация». Формула масштаба выводится в LaTeX
(`pn.extension("mathjax")`), ресурсы встраиваются (`pn.config.inline`),
сервер поднимается только на `127.0.0.1`, поэтому сеть не нужна. Источник
лежит в проекте как `reports/dash_*.py`, настройки — рядом в `dash_*.yaml`
(заголовок, прогоны, секции, пороги, порт); один и тот же файл работает
для разных проектов. Флаг `--check` собирает панель и печатает число
виджетов, блоков LaTeX и время сборки — так дашборд проверяется в CI
без браузера.

## Пакет для борта

```bash
simorph export-package --model models/det_kp.onnx --target rk3588 --target a733 \
    -o packages --project examples/demo/project.json --run <run_id>
simorph export-package --model models/det_kp.onnx --target rk3588 --convert
simorph verify-package packages/rk3588                        # манифест и суммы
```

Пакет — каталог на один борт: `manifest.yaml`, модели, конвейер,
калибровка, скрипты конвертации и `checksums.sha256`. Профили целей
описывают SoC и бюджеты: RK3588 (RKNN-Toolkit2, 6 TOPS, 4×A76 + 4×A55)
и A733 (ACUITY/NBG, 3 TOPS, 2×A76 + 6×A55); бюджеты по умолчанию —
`inference_p95_ms: 400`, `memory_mb: 512`. Манифест хранит sha256 каждого
файла и `manifest_hash` по содержимому без полей происхождения, поэтому
две сборки с одними входами дают один хэш, а `verify-package` ловит
и подменённый файл, и лишний. Скрипты `convert_rknn.py` и `convert_nbg.py`
самодостаточны и проверяют тулчейн: вендорские SDK не входят в зависимости
(NFR-LIC-03), конвертация включается флагом `--convert` и без SDK даёт
код 2 с подсказкой, а не исключение. Отсутствующая целевая модель —
предупреждение в отчёте сборки, а не ошибка.

## Графическая оболочка

```bash
simorph app                          # пустой проект в памяти
simorph app examples/demo/project.json
simorph app examples/demo/project.json --offscreen   # без дисплея
```

Рабочее место: дерево проекта слева, инспектор свойств справа, вкладки
разделов в центре, панели валидации и поиска — док-панели. Правки идут
через `QUndoStack` (Ctrl+Z / Ctrl+Y, лимит 100 шагов), проект
автосохраняется в `project.json.autosave` и восстанавливается после
аварийного завершения. Если проект уже открыт другим экземпляром, окно
работает в режиме «только чтение»: инспектор и сохранение блокируются.
Тема переключается в меню «Вид → Тема» без перезапуска.

Вкладка «Профиль» открывается двойным кликом по разделу в дереве: слева
JSON-редактор с подсветкой, номерами строк и сворачиванием блоков, справа
таблица параметров с правкой класса и вектора, вкладки проекции и отчёта,
кнопки импорта и экспорта.

Вкладка «3D-сцена» (F6, меню «Проект») показывает мир: орбита — левой
кнопкой мыши, панорамирование — правой или средней, зум — колесом. На
панели: сброс к seed, снимок, фотореализм, колебания камеры, осадки и
время суток; внизу — FPS, время кадра и число объектов. Фотореализм
и колебания меняют только предпросмотр, ground truth остаётся прежним.

Вкладка «Агент» (F7, меню «Проект») показывает состав агента: слева
дерево звеньев, сенсоров, актуаторов и `P_hw` по группам, справа —
предпросмотр с той же орбитой, панорамированием и зумом. На панели: сброс
вида, переключатель зон обслуживания и экспорт URDF; внизу — время сборки,
число звеньев, коллизий и ошибок валидации. Предпросмотр пересобирается
через 300 мс после правки документа, поэтому набор текста в инспекторе
не дёргает сцену на каждый символ.

Вкладка «Миссия» (F8, меню «Проект») — три панели одного документа:
слева граф по слоям с подсветкой циклов и недостижимых узлов, в центре
выбранный элемент (тайминги, поза, зона, сенсор, переходы), справа бюджет,
расписание с критическим путём и замечания миссии. Правка поля применяется
одной командой undo и сразу перестраивает граф и расписание; элементы
можно добавлять и удалять. Компактный режим скрывает панель графа, сохраняя
выбор, — на узком экране остаются элемент и параметры.

Вкладка «Симуляция» (F9, меню «Проект») запускает тот же headless-раннер
в фоновом потоке: слева состояние супервизора, часы, кадры, потери и вклад
ступеней, справа интервалы план/факт и журнал событий. Доступны масштаб
времени, длительность, пауза, шаг вперёд и остановка; оконный режим не
блокирует интерфейс и даёт те же метрики, что `simorph sim run`.

Вкладка «Конвейеры» (F10, меню «Проект») — три панели одного документа:
слева граф по слоям с подсветкой циклов, неизвестных типов и узлов вне
потока, в центре выбранный узел (бюджет и параметры JSON), справа сводка
плана и таблица метрик прогона с журналом событий. Узлы добавляются,
удаляются и переставляются, рёбра связываются по портам: несовместимый
порт, дубль и цикл блокируются с причиной. Любая правка — одна команда
undo. Внизу — read-only исходники: дерево каталога, текст с подсветкой,
снимок хэшей и проверка `stale`.

Вкладка «Журналы» (F11, меню «Проект») открывает `run.sqlite` рядом
с проектом: слева прогоны с фильтрами по виду, статусу и тексту, справа
ряды выбранного прогона — метрики или события с фильтром по имени,
префиксу и интервалу времени. Выборка читается в фоновом потоке, поэтому
интерфейс не замирает на 10^5 строках; текущую выборку можно выгрузить
в CSV или Parquet.

Вкладка «Отчёт» — конструктор из двух панелей: слева прогон, секции,
форматы и порог `k.p95`, справа готовый документ. Любое изменение
пересобирает отчёт целиком, поэтому предпросмотр — это ровно тот HTML,
что уходит в файл (PNG подтягиваются из каталога предпросмотра), и
расхождение «в окне одно, в экспорте другое» невозможно по построению.
Сборка занимает доли секунды; «Сохранить…» пишет выбранные форматы
в каталог.
